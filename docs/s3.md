# S3-compatible endpoint

Existing S3 code (boto3, aws-cli, aws-sdk-*) can use NEAR Drive by changing only the endpoint and the keys. The
endpoint runs on your machine, encrypts with your key and signs with your NEAR key, so it stays end-to-end encrypted.

```sh
near drive up          # background service on 127.0.0.1:9000 (loopback only); prints the AWS_* exports
near drive down        # stop it
near drive s3-proxy    # the same endpoint in the foreground (containers, systemd); same flags
```

```python
import boto3
s3 = boto3.client("s3", endpoint_url="http://127.0.0.1:9000",
                  aws_access_key_id=AK, aws_secret_access_key=SK, region_name="us-east-1")
s3.upload_file("ckpt.bin", "alice.near", "ckpts/step-100.bin")     # = near://alice.near/ckpts/step-100.bin
```

Options:
- The S3 keys are generated once and stored (owner-only) in `~/.near-drive/s3-proxy.json`, or pass
  `--access-key` / `--secret-key` (`NEAR_DRIVE_S3_ACCESS_KEY` / `NEAR_DRIVE_S3_SECRET_KEY`).
- `--listen 127.0.0.1:9100` picks another port (loopback addresses only).
- `--public-prefix weights/public/` stores keys under that prefix unencrypted.
- `--bucket other.near` also lists that namespace in ListBuckets.

## Compatibility

- **Addressing.** Bucket = NEAR account, key = path. Path-style URLs (`http://127.0.0.1:9000/alice.near/key`) work,
  and so does virtual-host style when the host is `alice.near.localhost`.
- **Auth.** SigV4 header and presigned auth, including signed `aws-chunked` (every chunk signature verified),
  `UNSIGNED-PAYLOAD` and `STREAMING-UNSIGNED-PAYLOAD-TRAILER`. `x-amz-checksum-{crc32,crc32c,crc64nvme,sha1,sha256}`
  and `Content-MD5` are checked. SigV2 is accepted too, because botocore < 1.36 presigns with it. Requests fail on a
  bad signature, a wrong key or more than 15 minutes of clock skew.
- **Operations.**
  - Buckets: ListBuckets, Head/Create/DeleteBucket (own namespace only, as no-ops), GetBucketLocation.
  - Objects: Put/Get/Head/Delete Object with Range and the If-* conditions, DeleteObjects, CopyObject.
  - Listing: ListObjects v1/v2 with prefix, delimiter, pagination and `encoding-type=url`.
  - Multipart: Create / UploadPart / UploadPartCopy / Complete / Abort / ListParts / ListMultipartUploads. Parts are
    staged in `~/.near-drive/s3-staging` and uploaded on completion.
  - Not supported (`NotImplemented`): ACLs, policies, tagging, versioning, lifecycle, CORS, SSE-C and SigV4a.
- **Metadata.** Content-Type is kept. `x-amz-meta-*` goes into an encrypted sidecar object `<key>.drive-s3meta`,
  hidden from listings (keys ending in that suffix are reserved). The ETag is the first 32 hex characters of the
  manifest id, quoted (multipart objects have no `-N` suffix). Last-Modified is the write time.
- **Keys** must be valid NEAR Drive paths: no empty, `.` or `..` segments and no trailing `/`; others get
  `InvalidArgument`.
